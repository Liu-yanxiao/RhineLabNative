# 歌单列结构、清晰度与连续打开验证

2026-10-14。当前交付：`/Users/lyx/Applications/RhineMusicNative.app`。

## 功能定义

每个音乐库列对应一个歌单；行是该歌单的歌曲，按歌单长度循环映射。重复歌曲在不同歌单有不同场景身份。空歌单仅显示占位卡。主页左右切列、上下浏览歌曲；详情中左／上为上一首，右／下为下一首，保持当前歌单。暂停换歌不会自动播放。搜索结果作为一列临时歌单，不自动保存。

内置 3 份示例，共 20 首：明日方舟 8 首、流行精选 6 首、钢琴与片刻 6 首。明日方舟曲目／封面取自 [官方塞壬唱片](https://monster-siren.hypergryph.com/music/)，播放时使用官方公开歌曲接口；另外两份沿用网易云元数据与现有音源。实际时长由原生媒体解析核对，启动不执行在线搜索。

## 清晰度与卡顿调查

改动前诊断：1440×810 点、2× 屏幕实际只绘制 1350×759，像素比例 0.469；进入约 1.4 秒后切到单独查看器，封面中心跳动 63.5 点。图片固定缩略为 512，进一步限制打开后的细节。

改动后同一诊断：2880×1620，像素比例 1.000；中途跳动 0.0 点。移动和静止使用相同尺寸、4× MSAA，音乐模式关闭景深模糊。选中的详情封面最高按 1536 解码；普通封面仍用 512 缩略。图片解码在后台执行，同时最多 3 个请求；大图只缓存最近 2 张，普通缩略和标签缓存有上限。更换图片只使对应标签失效。

几何改用 RhineMusicV030 自带的 `music-cd.glb`，取代压扁原档案盒的近似模型。音乐玻璃保留参考版磨砂效果，打开时不再降到原档案查看器的镜面粗糙度。打开、换歌、返回都使用 ArchiveEngine，同一镜头连续完成；换歌不再等待档案解密时间。封面水平旋转上限约 54°，略大于参考版 46°；新增小幅垂直倾斜、轻微捏合缩放和复位。

## 验证与结果

- `swift test`：10 项通过，覆盖歌单列／歌曲循环、重复歌曲场景身份、封面交互边界及复位、播放取消、用户数据往返、帧率切换等。
- `--render-check`：原生像素与连续进入均 PASS。
- `--playlist-check`：实际明日方舟音频推进、打开、同歌单下一首、暂停换歌仍暂停、返回完整流程 PASS。临时曲库测试，不修改用户曲库与偏好。
- 原生窗口检查：主页 Right 从明日方舟切到流行精选，Left 返回；Down 浏览 Renegade 后 Enter 打开。详情 Right 选 Radiant，Up／Left／Down 均仍在明日方舟 8 首歌曲内，保持暂停。
- 2880×1620 的独立 GPU 测量：主界面平均 5.22 ms，p95 7.03 ms；打开过渡平均 2.68 ms，p95 3.27 ms，最大 3.53 ms；详情平均 2.46 ms。此测量使用静态测试目录，不代表包含所有封面／其他应用负载时的全程帧时间。
- 当前原生窗口经过封面加载、详情、换歌与返回后物理占用 350.4 MiB，约 367 MB。仅计本程序进程；比早期低像素版本更高，不能与不同画质／曲库状态当作严格同条件比较。
