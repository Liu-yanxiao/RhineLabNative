## 两项独立的设计修正

1. 子页面的风格：搜索、收藏、音乐库、设置与临时播放队列共用原档案界面的 ModalFrame、ModalTitle、MiSans、主题色与细线。输入改为行式底线，设置用文字选择与编号分区，去掉另一套大块表单样式。主页面三维阵列与取景保留。
2. 播放界面的参考：借鉴 V0.3.0 中可操控封面与右侧曲目阅读区、轻量顶部播放控件、歌名定位和编号曲目。原生详情按当前歌单的数据重新排版，不复制专辑资料表或页签；搜索直接试听的歌曲有临时队列与歌曲信息。没有新增预设分类或继续扩展歌单数据功能。

## 原生交互与播放

- 不运行 WKWebView 或 Node。SwiftUI 负责界面，Metal 负责玻璃阵列与三维封面，AVPlayer 负责在线播放。
- 自由查看路径沿用 ViewerEngine，拖动旋转、右拖平移、滚轮缩放、复位，增加触控板捏合和旋转。音乐模式的旋转可跨越两极，平移与拉远不再使用原来的固定上限。
- 实际窗口确认拖动会改变三维视角，返回后画面仍可继续交互。透明界面层的事件转发与切换引擎时显示链唤醒已修正。
- 新细线进度条实际拖动使暂停歌曲从 0:23 跳到 3:12；辅助功能增减进度与播放/暂停控件也检查了。
- `swift test`：7 项通过，覆盖取消解析、防止旧解析重启播放、已有收藏数据往返、空启动、旧分类缓存不导入、封面和渲染预算、自由手势边界。没有为视觉数值编写镜像测试。
- 最终包运行 `--music-check`：星海和 HYW 均 PASS，实际静音播放推进、暂停/继续、跳转、下一首。UI 另实测搜索返回结果和星海歌曲播放推进。
- Release 构建与严格签名验证通过；包约 57 MB。

## 内存调查

以 macOS `footprint` 的进程物理占用为口径。只记录由播放器启动的相关进程，未计入其他应用的 WebKit/Node。

旧网页版本的组成：

| 进程 | PID | 物理占用 MiB |
| --- | --- | ---: |
| com.apple.WebKit.WebContent | 43830 | 1248.2 |
| com.apple.WebKit.GPU | 43828 | 279.1 |
| RhineLab | 43826 | 156.9 |
| node | 43827 | 38.5 |
| com.apple.WebKit.Networking | 43829 | 27.2 |

相关进程合计 1749.6 MiB。占用主要来自 WebContent 与 WebKit GPU；Swift 宿主还提前创建了原生 Metal 渲染器，因此同一应用同时承担网页与原生场景的成本。

恢复原生后，首次空库待机测得 199.5 MiB；本轮打开设置、搜索并实际播放后的测量为 168.5 MiB（PID 46207）。最终包完成播放、三维详情旋转、返回、音乐库、昼夜设置检查后回到主页面，测得 142.8 MiB（PID 46332）。播放器仅有原生进程。旧网页版有较多预加载曲目，而当前原生测试库为空，因此这组数字用于说明已测试状态和进程来源，不是相同曲库下的严格基准或恒定占用保证。

额外约束：默认渲染最多 2073600 像素；音乐封面用 ImageIO 缩略到最长边 512 像素并限制缓存；标签与渲染分辨率缓存有上限；音乐模式不解码原档案三轨背景配乐；静止场景暂停显示链。
